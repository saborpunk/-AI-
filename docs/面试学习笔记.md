# 第一阶段面试学习笔记

第二阶段已补充 Java → Python 实际业务调用。新知识点及逐文件说明见 [第二阶段说明](第二阶段说明.md)，其中明确区分 HTTP 契约测试、真实双服务冒烟和未实现的 AI 能力。

当前能陈述的成果：搭建 Java 与 Python 两个最小 HTTP 服务，完成构建、健康检查和测试，解决本地工具、代理与配置问题。不能说已经做完 AI 客服或高并发系统。

## 核心代码在哪里

- `backend-java/src/main/java/com/seedassistant/SeedAssistantApplication.java`：Java 入口。`main` 启动 Spring，`@SpringBootApplication` 启用自动配置与组件扫描。
- `backend-java/src/main/resources/application.yml`：应用配置。只绑定本机，只开放 health；这不是完整安全鉴权。
- `backend-java/pom.xml`：依赖和构建清单。parent 统一依赖版本，Java 版本为 21，插件把程序打包为可执行 jar。
- `backend-java/src/test/java/com/seedassistant/HealthEndpointTest.java`：启动真实随机端口服务，检查健康 HTTP 200、内部配置端点 404。
- `ai-service/app/main.py`：FastAPI 定义路由，Pydantic 限定响应字段；`Literal` 限定为固定值，避免 Mock 标识漂移。
- `scripts/smoke.ps1`：从进程外真实请求两个服务；进程内 Python 测试不能替代这个检查。

## 可以练习的追问

**为什么有 Java 和 Python？** Java 管正式业务和持久记录，Python 负责可替换的 AI 流程；当前先验证各自启动。代价是两套依赖、两套测试和网络故障处理，后续不能让 Python 直接修改业务台账。

**FastAPI 和 Uvicorn 有什么区别？** FastAPI 决定某个请求由哪个函数处理，Uvicorn 负责监听端口和接收网络请求。就像办事规则与负责接待的工作人员。

**为什么 health=UP 不代表项目完成？** 它只说明当前服务能响应。数据库是否保存、生成是否可靠、依据是否真实、用户是否省时间，都要独立检查。

**为什么用虚拟环境和 Wrapper？** 前者隔离 Python 依赖，后者统一 Maven 工具版本，减少“我的电脑能运行，你的不能”。固定版本仍需后续安全维护。

**单元测试、集成测试和冒烟测试如何区别？** 单元测试查单个规则；集成测试查组件配合；冒烟测试从实际运行入口查最基本路径。本阶段 Java 测试是启动服务的集成测试，Python 是进程内接口测试，脚本是进程外冒烟测试。

## 本阶段学习顺序

1. HTTP 请求、端口、状态码、JSON：自己访问两个健康接口。
2. Java main、注解、Spring 自动配置：解释为何无需单独安装 Tomcat。
3. Maven 生命周期：verify 会编译、测试、打包；理解为什么测试失败不能继续发布。
4. Python 函数、类型注解、venv：从返回值找到实际 JSON 字段。
5. 环境变量与配置优先级：解释 DEBUG 为什么能影响程序。
6. Git commit 与 push：提交是本地快照，推送才上传到远程。
