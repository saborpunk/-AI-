# 技术决策与新手注解

## ADR-001：先启动两个最小后端，再接数据库

前端是商家看到的服务窗口；Java 后端是处理咨询规则的调度员；Python 后端是以后帮助起草回复的助手；MySQL 是保存正式记录的台账。当前先让调度员和助手各自开门，确认运行环境正常，再接台账。

| 归属 | 技术 | 具体作用与原因 | 代价及验证 |
| --- | --- | --- | --- |
| Java 后端 | Java 21 JDK | JDK 是编译和运行 Java 的工具箱；Java 21 是计划中的语言基线 | 开发机需要工具箱；用 java -version 和编译确认 |
| Java 后端 | Spring Boot 4.0.8 | 自动装配 Web 服务，像配好水电的服务站；main 方法启动整个应用 | 需学习依赖注入和配置；真实启动测试验证 |
| Java 后端 | Spring MVC starter | 将 HTTP 请求分配给处理方法，自带 Tomcat 接待请求 | 请求线程不是无限的，后续 AI 调用必须限制超时 |
| Java 运维 | Actuator | 标准体检窗口 /actuator/health；当前只报告服务能响应 | UP 不代表所有业务正确；检查健康并验证 env 端点未暴露 |
| 构建 | Maven Wrapper | 固定装配工具版本，pom.xml 是配件清单；执行测试并打包 jar | 首次需联网下载；实际运行 wrapper 验证 |
| Python 后端 | Python 3.12 | AI 流程的编程语言，与原计划保持一致 | 与 Java 分别管理环境；通过专用虚拟环境运行 |
| Python 后端 | FastAPI | 把 Python 函数变成 HTTP 窗口，并生成 OpenAPI 接口清单 | 它本身不生成智能回复；用实际请求和接口契约测试验证 |
| Python 后端 | Pydantic | 定义返回单据的格式，限制 status、service、mode 合法值 | 格式正确不等于事实正确；后续另测依据校验 |
| Python 运行 | Uvicorn | 实际监听 8000 端口的接待员，收到请求后交给 FastAPI | 必须启动服务器才可从 Java 访问；只监听本机 |
| 测试 | Spring Boot Test / JUnit | 在随机端口启动应用，检查健康与端点暴露配置 | 启动比普通函数测试慢，但能发现装配问题 |
| 测试 | pytest / httpx | pytest 执行检查，httpx 支持 FastAPI 测试客户端 | 进程内测试不能代替真实端口冒烟，两者都做 |
| 工具 | Python venv / pip | venv 创建项目独立工具柜，pip 安装配件；用户已安装 Python 3.12，因此无需 uv | requirements.txt 固定安装版本，不影响系统其他项目 |
| 前端（后续） | Vue 3 / TypeScript / Vite / Element Plus | 页面组件、字段类型检查、开发打包、现成表格表单 | 当前不安装；到工作台阶段逐项解释和验证 |
| 存储（后续） | MySQL 8.4 / MyBatis / Flyway | 台账、执行 SQL 的查询员、按编号升级台账格式的记录 | 当前不引入；持久化阶段用真实数据库验证 |

### 当前调用流程

浏览器或检查脚本 → Java 的 /actuator/health → 返回 UP。

浏览器或检查脚本 → Uvicorn → FastAPI /health → Pydantic 限定字段 → 返回 UP、seed-ai、mock。

两条请求目前相互独立。Java→Python 的业务调用在模拟生成阶段实现，不把两个健康接口称为业务闭环。

### 为什么省去其他组件

骨架没有持久业务，因此不引入数据库驱动；没有登录页面，因此安全模块留在鉴权阶段；没有生成任务，因此不预建线程池、队列、缓存和重试框架。这样遇到启动错误可以先定位环境和 Web 装配，减少排错变量。
