# 开发记录

## 阶段 0—1：环境与后端骨架（2026-09-09）

范围：固定 MVP 边界；建立 Java/Python 可启动服务、健康接口、测试、构建入口和运行文档。不提前实现数据库和业务模块。

环境：Windows x64；Temurin JDK 21.0.12.1（D:/dev/sdk）；Maven 3.9.16（用户下载的 ZIP，随后生成并验证 Wrapper）；Python 3.12.10；Node 24.20.0、npm 11.19.0 已有但本阶段不使用。Docker 未验证可用，下一阶段处理。

| 问题 | 原因/证据 | 解决与边界 |
| --- | --- | --- |
| 工具下载中断 | 上一轮出现 EOF、证书吊销服务不可达 | 用户完成下载，复用本地安装包；没有把残缺 ZIP 当安装完成 |
| Python 环境混乱 | 默认 python 指向 3.14，py 曾找不到安装 | 显式使用已安装的 3.12 创建项目 .venv，不改动其他版本 |
| pip 下载失败 | SSL EOF 和 ProxyError | 仅当前安装进程 NO_PROXY=*，使用清华 HTTPS 镜像成功下载 |
| Maven TLS 握手失败 | Central 连接终止 | 当前命令显式使用用户已配置的 127.0.0.1:7897 代理，仍用 Central；不持久修改网络配置 |
| Maven 把版本当构建阶段 | 未加引号的 -Dmaven=3.9.16 被 PowerShell 拆分 | 对完整 -D 参数加引号，Wrapper 生成成功 |
| 环境脚本项目路径为空 | Windows PowerShell 读取无 BOM 中文注释出现兼容问题 | 执行脚本使用 ASCII 注释，中文说明保留在 README，复测环境变量正确 |
| Spring 输出大量 DEBUG 日志 | 环境中 DEBUG=release 被配置系统读取，环境变量优先于 application.yml | 仅在项目终端设置 DEBUG=false；不能只改 YAML 就宣称解决 |

核心代码与学习点见面试学习笔记；实际检查结果见测试报告。依赖安装只在项目虚拟环境和缓存目录内进行。Maven Wrapper 首次验证曾使用默认用户缓存，修复环境脚本后改为项目 .m2 缓存。
