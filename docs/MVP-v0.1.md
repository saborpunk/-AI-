# MVP v0.1 范围与分阶段验收

2026-09-08：用户确认开始逐阶段开发。本文件约束 MVP；整体计划书保留为长期路线，不能将其中所有功能提前加入。

## 核心流程

商家登录 → 手动录入文字咨询、类别和可选模拟批次 → Java 保存咨询并选择模拟依据 → Python Mock 生成草稿 → Java 校验引用并保存 → 商家编辑确认 → 复制到微信人工发送 → 查询历史。

状态：待处理 → 待确认 → 已确认。保留原问题、原草稿、证据快照和最终回复。确认不代表微信送达。缺资料时提示补充，Python 不可用时仍允许人工处理。

## 必须实现

单个配置账号登录退出；文字咨询的创建与分页查询；少量只读模拟批次和证据；有超时限制的 Java→Python 同步调用；证据引用校验；人工编辑确认；重复操作保护；服务失败提示；登录、列表、详情页面；数据库迁移、测试和启动说明。

同一咨询只允许一次正在执行的生成，最终由数据库条件更新保护，不能只靠按钮禁用。中断生成需要恢复为可重试状态。Mock 是确定性的模拟服务，不是真实大模型，不证明农业回答质量。

## 暂缓

真实资料和模型、语音识别、微信/抖音集成、交易合同、知识管理后台、多角色多租户、工单提醒、异步队列、Redis、消息中间件、向量数据库、百万数据压测、完整监控栈、云部署和开源贡献。

## 技术和目录

- frontend：后续 Vue 3 + TypeScript + Vite + Element Plus，浏览器 Fetch 请求 Java。
- backend-java：Java 21 + Spring Boot 4.0.x；逐步加入 Validation、Security Session、MyBatis 和 Flyway。
- ai-service：Python 3.12 + FastAPI + Pydantic + Uvicorn，Mock 阶段无外部模型调用。
- MySQL 8.4：正式记录；在数据库阶段加入，不用内存数据库冒充持久化验收。
- scripts：环境、启动和冒烟检查；docs：技术决策、开发记录、验证和学习资料。

## 开发顺序和验证

| 阶段 | 交付 | 验证方式 |
| --- | --- | --- |
| 0 环境 | 工具版本、缺项与本地配置 | 执行版本命令，确认运行环境和端口 |
| 1 骨架 | Java/Python 健康接口、构建入口 | 分别真实启动，请求健康接口，检查日志和自动测试 |
| 2 持久化 | MySQL/Flyway、咨询创建查询 | 真数据库迁移、非法输入、重启后读回 |
| 3 模拟生成 | 模拟依据和 Java→Python 草稿 | 有依据、缺批次、无依据、无效引用测试 |
| 4 审核可靠性 | 编辑确认、超时与重复操作 | 关闭 Python、并发请求、重启恢复、最终回复读回 |
| 5 工作台 | 登录及前端闭环 | 浏览器完整操作、未登录拒绝、注销、刷新恢复 |
| 6 MVP 验收 | 启动编排、完整 README 与报告 | 独立干净数据库按 README 重建并回归 |

每阶段先运行、排错、测试；阶段完成后提交并推送版本记录，并停止等待用户明确确认，再进入下一阶段（用户最新要求）。

## MVP 完成标准

新开发者按 README 启动；不需要模型密钥或真实资料；能演示正常、缺证据及 Python 故障三条路径；原始与最终记录可追溯并跨重启保存；自动测试和浏览器检查通过并留报告。

骨架通过只是第一阶段通过，不能称为完整 MVP、计划书 G1 通过、生产可用或高并发成果。
